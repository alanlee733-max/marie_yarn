# marie yarn — 홈페이지 v1 기획서

> 작성일: 2026-08-14 · 상태: 초안 (확정 전)

---

## 1. 프로젝트 개요

해외 뜨개실을 수입해 국내에 유통하는 사업의 공식 홈페이지를 구축한다.
v1은 **브랜드 · 카탈로그 사이트 + 네이버 스마트스토어 연결** 형태로, 최종 소비자(뜨개인)를 대상으로 한다.
사이트가 실을 보여주고 설득하는 역할을 맡고, 결제는 네이버가 처리한다.

### 1.1 결제 방식 — 왜 스마트스토어 링크인가

"네이버 결제"에는 두 가지가 있고 v1이 감당할 수 있는 것은 하나뿐이다.

| 방식 | 내용 | v1 적용 |
|---|---|---|
| **스마트스토어 링크** | 제품별 `구매하기` → 네이버 스토어 상품 페이지 | **채택**. 별도 심사·서버 개발 없음 |
| 네이버페이 결제형 API | 자체 사이트 안에서 결제창 호출 | 보류. 서버 + 가맹 심사 + 통신판매업 신고 필요 |

각 제품 데이터에 `naverProductUrl` 필드를 두고, 값이 없으면 스토어 메인으로 폴백한다.
나중에 결제형 API로 전환할 때 이 필드와 `naverUrl()` 함수만 교체하면 되도록 격리해 두었다.

### 1.2 v1의 전환 목표

| 우선순위 | 전환 행동 | 측정 |
|---|---|---|
| 1 | **네이버 스토어 이동** (구매 버튼 클릭) | 아웃바운드 클릭 수 |
| 2 | **입고 알림 신청** (이메일 등록) | 등록 이메일 수 |
| 3 | 제품 문의 / 도매 문의 | 문의 건수 |
| 4 | 인스타그램 · 카카오채널 유입 | 아웃바운드 클릭 |

스토어 이동이 1순위이지만 이메일 리스트도 계속 모은다.
품절·입고 예정 상품은 스토어로 보낼 수 없으므로, 그 트래픽을 흘려보내지 않으려면 알림 신청이 필요하다.

### 1.3 v1이 답해야 하는 질문

방문자가 사이트를 떠나기 전에 반드시 얻어가야 하는 정보:

1. 이 회사는 **어떤 실**을 수입하는가 (브랜드 · 원산지 · 소재)
2. 그 실은 **어떤 색**이 있는가 (컬러웨이 — 뜨개인이 가장 오래 보는 화면)
3. 그 실로 **무엇을 뜰 수 있는가** (굵기 · 게이지 · 권장 바늘)
4. **언제, 어디서 살 수 있는가** (입고 예정 · 알림 신청 · 오프라인 취급처)

## 2. 타깃 사용자

### 2.1 주 타깃 — 중급 이상 뜨개인

- 이미 여러 실을 써봤고 브랜드·소재를 구분한다.
- **소재 구성(%), 실 길이(m), 게이지, 권장 바늘 호수**를 반드시 확인하고 산다.
- 색상은 모니터 색이 아니라 **실물 스와치 사진**으로 판단한다.
- 인스타그램에서 실 정보를 먼저 접하고 검색으로 넘어온다.

**설계 함의:** 스펙 표를 접어두거나 생략하면 안 된다. 상세 페이지 상단 고정 영역에 노출한다.

### 2.2 부 타깃 — 입문자

- "이 실로 목도리를 뜰 수 있나?" 수준의 질문을 가진다.
- 굵기 용어(fingering / DK / worsted / bulky)를 모른다.

**설계 함의:** 굵기 필터에 한글 병기와 "이 굵기로 만들기 좋은 것" 설명을 붙인다.

### 2.3 잠재 타깃 — 뜨개방 · 공방 사장

- v1의 주 타깃은 아니지만 유입된다. 푸터에 **도매 문의 창구** 한 줄은 반드시 둔다.

## 3. v1 범위

### 포함 (In Scope)

- 홈 / 제품 카탈로그 / 제품 상세 / 브랜드 소개 / 회사 소개 / 문의 / FAQ
- 제품 필터 (브랜드 · 소재 · 굵기 · 색 계열)
- 컬러웨이 갤러리 (제품당 다수 색상)
- **네이버 스마트스토어 구매 연결** (제품별 링크 + 스토어 폴백)
- 입고 알림 · 뉴스레터 이메일 수집
- 문의 폼 (일반 + 도매 구분)
- 반응형 (모바일 우선 — 뜨개인 트래픽은 인스타 경유 모바일이 대부분)
- SEO 기본 (메타 태그, OG 이미지, sitemap, robots, JSON-LD)
- 개인정보처리방침 · 이용약관 · 사업자정보 푸터

### 제외 (Out of Scope — v2 이후)

- 자체 장바구니 · 결제창 · 주문 관리 (네이버가 처리)
- 회원가입 · 로그인 · 마이페이지
- 실시간 재고 연동
- 관리자 페이지 (v1은 코드/파일로 제품 관리)
- 다국어 (한국어만)
- 리뷰 · 커뮤니티 · 도안 판매

### 4.1 페이지별 상세

#### 홈 `/`

| 섹션 | 내용 |
|---|---|
| 히어로 | 실 클로즈업 대형 이미지 + 한 줄 브랜드 메시지 + `제품 보기` CTA |
| 취급 브랜드 | 수입 브랜드 로고 스트립 (→ `/brands`) |
| 신규 / 추천 실 | 카드 3~6개, 컬러칩 미리보기 포함 |
| 컬러 스토리 | 색 계열별 큐레이션 ("이번 시즌 뉴트럴") — 시각적 하이라이트 |
| 브랜드 스토리 | 왜 이 실을 수입하는가, 짧게 2~3문단 + `더 보기` |
| 입고 알림 | **이메일 입력 폼** — 페이지 하단 고정 배치 (v1 핵심 전환 지점) |
| 인스타그램 | 최신 게시물 그리드 (v1은 정적 이미지 링크로 시작) |

#### 제품 카탈로그 `/products`

- 좌측(데스크톱) / 상단 시트(모바일) 필터: **브랜드 · 소재 · 굵기 · 색 계열 · 입고 상태**
- 정렬: 신상품순 · 이름순
- 카드: 실타래 사진 · 제품명 · 브랜드 · 굵기 뱃지 · **컬러칩 미리보기(최대 8개 + `+n`)** · 상태 뱃지(입고 예정 / 품절)
- 필터 상태를 URL 쿼리에 반영 (`?brand=...&weight=...`) — 공유·뒤로가기 대응

#### 제품 상세 `/products/[slug]`

레이아웃: 좌측 이미지 갤러리 / 우측 스펙 (모바일은 세로 스택)

- **이미지**: 실타래 컷 · 스와치(뜬 조직) 컷 · 색상별 컷
- **컬러웨이 선택기**: 색상 칩 그리드, 선택 시 이미지 전환 + 색상명/코드 표시
- **스펙 표** (접지 않고 전부 노출):
  소재 구성 / 중량(g) / 실 길이(m) / 굵기 / 권장 게이지 / 권장 바늘·코바늘 호수 / 세탁 방법 / 원산지
- **필요 볼 수 안내**: "목도리 1개 ≈ 3볼" 같은 참고 문구 (계산기는 v2)
- CTA: `입고 알림 받기` · `이 실 문의하기`
- 하단: 같은 브랜드의 다른 실

#### 브랜드 상세 `/brands/[slug]`

- 브랜드 히스토리 · 원산지 · 철학 · 대표 이미지
- 해당 브랜드 제품 목록

#### 실 고르기 가이드 `/guide`

입문자용 SEO 유입 페이지. 검색 트래픽을 실제로 만드는 페이지다.

- 굵기 체계 표 (lace / fingering / sport / DK / worsted / bulky / jumbo + 한글 · 권장 바늘 · 적합 작품)
- 소재별 특징 (메리노 / 알파카 / 실크 / 모헤어 / 코튼 / 린넨)
- 게이지 읽는 법 · 세탁 기호 읽는 법

#### 문의 `/contact`

- 탭 구분: **일반 문의** / **도매·취급 문의**
- 일반: 이름 · 이메일 · 문의 유형 · 내용
- 도매: 상호 · 사업자등록번호 · 담당자 · 연락처 · 관심 브랜드 · 예상 수량
- 개인정보 수집·이용 동의 체크박스 **필수**

## 5. 제품 데이터 모델

v1은 결제가 없지만, **컬러웨이를 배열로 잡아두면 v2에서 장바구니를 붙일 때 옵션 구조를 다시 만들지 않아도 된다.** 처음부터 아래 형태로 간다.

```ts
type YarnWeight =
  | 'lace' | 'fingering' | 'sport' | 'dk' | 'worsted' | 'bulky' | 'jumbo';

type Stock = 'in_stock' | 'incoming' | 'sold_out' | 'discontinued';

interface Colorway {
  code: string;          // 브랜드 색상 코드 (예: "M-102")
  name: string;          // 색상명 (예: "오트밀")
  hex: string;           // 필터·칩 렌더링용 근사값
  colorFamily: ColorFamily; // 색 계열 필터용
  image: string;         // 실물 사진 (필수 — hex는 어디까지나 보조)
  stock: Stock;
}

interface Product {
  slug: string;
  name: string;
  brandSlug: string;
  description: string;

  // 스펙 — 뜨개인이 구매를 결정하는 핵심 정보
  fiber: { material: string; percent: number }[]; // [{메리노울, 80}, {실크, 20}]
  weightGram: number;        // 1볼 중량
  lengthMeter: number;       // 1볼 실 길이
  yarnWeight: YarnWeight;
  gauge: string;             // "10cm x 10cm = 22코 30단"
  needleSize: string;        // "4.0 ~ 4.5mm"
  hookSize?: string;
  careInstructions: string;  // "손세탁 · 30도 이하 · 뉘어서 건조"
  origin: string;            // 원산지

  colorways: Colorway[];
  images: string[];          // 대표 이미지 (스와치 컷 포함)

  retailPrice?: number;      // v1은 참고가 (표시 여부는 운영 판단)
  stock: Stock;
  releasedAt: string;        // 신상품 정렬용
  featured: boolean;
}

interface Brand {
  slug: string;
  name: string;
  nameKo: string;
  country: string;
  logo: string;
  heroImage: string;
  story: string;
}
```

**저장 방식 (v1):** `content/products/*.json`, `content/brands/*.json` — 빌드 시 정적 생성.
제품 추가는 JSON 파일 추가 + 이미지 업로드 + 커밋. 제품 수가 50개를 넘거나 비개발자가 직접 등록해야 하는 시점에 Headless CMS로 이관한다 (모델 그대로 유지 가능).

## 6. 디자인 방향

실은 **촉감과 색**으로 팔린다. 사진이 주인공이고 UI는 물러서야 한다.

- **레이아웃**: 여백을 넉넉히. 카드 그리드는 촘촘하기보다 크게.
- **컬러**: 따뜻한 뉴트럴 베이스(오프화이트 · 크림 · 웜그레이) + 포인트 1색.
  UI가 채도를 가지면 실 색이 죽는다. **회색조 배경 위에 실 색만 살린다.**
- **타이포**: 본문 Pretendard, 헤드라인 세리프(본명조 계열) — 수입 브랜드의 공예적 무게감.
- **이미지 비율**: 제품 카드 4:5(세로) — 실타래는 세로 프레임이 잘 맞고 모바일 점유율이 좋다.
- **컬러칩**: 원형이 아닌 **모서리 둥근 사각형**. 실 색 면적을 더 크게 보여준다.
- **다크모드**: v1 제외. 실 색 재현이 배경색에 좌우되므로 라이트 단일 테마로 고정한다.

## 7. 기술 스택

v1은 **정적 HTML + 바닐라 JS**로 먼저 만든다. 화면과 데이터 구조를 눈으로 확인하는 것이 우선이고,
빌드 도구 없이 브라우저로 파일을 열면 바로 보이는 편이 검토 속도가 빠르다.

| 영역 | v1 (현재) | v2 전환 시 |
|---|---|---|
| 구조 | 정적 HTML 멀티 페이지 | Next.js 15 App Router |
| 스타일 | CSS 커스텀 프로퍼티 (`assets/css/style.css`) | 동일 토큰을 Tailwind 설정으로 이관 |
| 데이터 | `assets/js/data.js` (JS 객체) | `content/*.json` + TypeScript 스키마 |
| 이미지 | CSS로 그린 실타래 플레이스홀더 | 실제 사진 + `next/image` |
| 결제 | 네이버 스마트스토어 링크 | 네이버페이 결제형 API (선택) |
| 폼 | 미연동 (안내 문구만 표시) | Route Handler + Resend |
| 배포 | 정적 호스팅 (Vercel · Netlify · Cloudflare Pages) | 동일 |

`data.js`의 객체 구조는 5장 데이터 모델과 1:1로 맞춰 두었다.
Next.js로 옮길 때 이 파일이 그대로 JSON이 되므로 데이터를 다시 만들 필요가 없다.

### 현재 파일 구조

```
index.html         홈
products.html      카탈로그 (필터 · 정렬)
product.html       제품 상세 — ?slug=fjord-merino
brands.html        브랜드 목록
guide.html         실 고르기 가이드
about.html         회사 소개
contact.html       문의 (일반 / 도매 탭)
faq.html           자주 묻는 질문
privacy.html       개인정보처리방침 (오픈 전 작성 필요)

assets/css/style.css
assets/js/
  data.js          ★ 사이트 설정 · 브랜드 · 제품 데이터
  main.js          공통 유틸 · 제품 카드 · 구매 버튼
  home.js  catalog.js  product-detail.js  brands.js  contact.js
```

## 8. 개발 마일스톤

| 단계 | 내용 | 산출물 |
|---|---|---|
| M1 | 디자인 토큰 · 헤더/푸터 · 레이아웃 | ✅ 완료 |
| M2 | 데이터 모델 · 샘플 제품 데이터 | ✅ 완료 (`assets/js/data.js`) |
| M3 | 카탈로그 · 필터 · 제품 상세 · 컬러웨이 | ✅ 완료 |
| M4 | 홈 · 브랜드 · 소개 · 가이드 · FAQ | ✅ 완료 |
| M5 | 실제 브랜드/제품 데이터 교체 · 제품 사진 | 콘텐츠 대기 |
| M6 | 네이버 스토어 URL 연결 | 스토어 개설 후 |
| M7 | 문의 폼 · 구독 폼 메일 연동 | 미착수 |
| M8 | 개인정보처리방침 작성 · SEO · OG · 배포 | 오픈 전 |

M1~M4는 샘플 데이터로 완료했다. 남은 병목은 개발이 아니라 **제품 사진과 스펙 확보, 그리고 스마트스토어 개설**이다.

## 9. 준비가 필요한 것 (운영 측)

개발과 병렬로 준비해야 오픈이 밀리지 않는다.

**브랜드**

## 10. v2 로드맵 (참고)

1. **자체 커머스** — 네이버페이 결제형 API 또는 국내 PG 연동, 컬러웨이별 재고 관리
   (네이버 수수료를 줄이고 고객 데이터를 직접 확보하려면 필요하다. 다만 트래픽이 붙기 전에는 스토어 연결이 낫다.)

5. **콘텐츠** — 무료 도안, 저널, 실 조합 추천

## 11. 미결정 사항

1. ~~소비자가 표시 여부~~ → **표시하기로 결정.** 네이버 스토어로 보내는 이상 가격을 숨기면 클릭률이 떨어진다.
   다만 홈페이지에는 정가를, 할인은 스토어에만 두는 것을 원칙으로 한다 (FAQ에 그렇게 안내해 두었다).
2. **가격 동기화** — 홈페이지와 스토어 가격이 어긋나면 신뢰를 잃는다. 수기 관리 주기를 정하거나,
   가격을 아예 표시하지 않고 "스토어에서 확인"으로 갈지 판단이 필요하다
3. **오프라인 취급처 안내** — 이미 납품 중인 뜨개방이 있다면 `/stores` 페이지 추가 검토
4. **입고 알림 발송 수단** — Resend 직접 발송 vs 스티비·메일침프 등 뉴스레터 서비스 연동
5. **제품 수량** — 오픈 시점 몇 개 품목으로 시작하는지에 따라 필터 UI 복잡도가 달라진다
